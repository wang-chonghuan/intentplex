Today I shared a T2P (Ticket to PR) skill I’ve been developing with the team.

T2P is a #harnessengineering automatic workflow that covers the full lifecycle from creating a Linear ticket to completing development, testing, documentation updates, and merging the PR.

Its key characteristics are:

1. Ensures every ticket implementation satisfies the stated requirements without drifting out of scope.

2. Ensures sufficient test coverage.

3. Requires both Codex review and project-specific rules review to pass.

4. Requires relevant project documentation to be updated.

5. Blocks PR merges if any of the above conditions are not met.

6. Preserves maximum freedom during the design and development phase: engineers can work spec-first, use vibe-coding, or delegate the implementation entirely to an agent.

7. Captures the development process for each ticket so the work can be retrospectively reviewed and analyzed.
