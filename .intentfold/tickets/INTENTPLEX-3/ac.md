# AC — INTENTPLEX-3（grill 前草稿）

工单的验收标准是权威来源，本文件只是可执行的检查计划。跑在本工单端口 **53003** 的 dev server 上
（`npm run dev -- --port 53003`），desktop 1280×800 与 mobile 390×844 两个视口。

已知噪声：站点无 favicon，浏览器隐式请求 `/favicon.ico` 会记一条 404 console error，按来源 URL
排除（沿用 INTENTPLEX-1/2 的做法）。

## AC1 — 两栏是 LinkedIn 的真实内容，倒序，数量对得上

**怎么查.** 抓取产出的 JSONL 里记录了每条的来源 URL / URN 与条数；导入脚本产出的 Markdown 文件
数与之相等。页面上：
1. `/posts` 与 `/articles` 的行数分别等于导入的条数；
2. 各自的日期序列非递增；
3. 随机抽三条，页面标题与 LinkedIn 上同名条目一致，`source` frontmatter 指回原文 URL。

**什么算通过.** 三条成立，且**抓取报告里的条数与 LinkedIn 自报的条数一致**——articles 是 11，
posts 的目标数在 grill 后确定（见下）。

## AC2 — article 详情页读得到正文，Markdown 结构渲染正确

**怎么查.** 打开至少两篇 article 详情页，断言：
1. 正文段落数 ≥ 3；
2. 页面里存在至少一个由 Markdown 生成的结构元素（`h2`/`h3`、`ul`/`ol`、`a`、`code` 之一），
   而不是整篇只有 `p`；
3. 正文不含未解析的 Markdown 字面量（不出现行首 `## `、裸 `](` 之类）。

**什么算通过.** 三条都成立。

## AC3 — 加减内容只动 Markdown，缺字段构建失败

**怎么查.**
1. `grep -rn` 确认 `src/` 下没有任何硬编码的条目内容（正文/标题不再出现在 `.ts` 里）；
2. 往 `content/posts/` 放一个新的 `.md`，`npm run build` 后该条出现在 `/posts`；删掉再 build，
   它消失。全程不碰 `.ts`；
3. 造一个缺 `date` 的 `.md`，`npm run build` **非零退出**并指名是哪个文件缺哪个字段。

**什么算通过.** 三条都成立，尤其第 3 条必须是构建失败而不是静默跳过。

## AC4 — 单语条目可读且有标注，补翻译不改结构

**怎么查.**
1. 界面切到中文，打开一条只有英文的条目，断言正文可读（非空）且页面上有明确的语言标注；
2. 给该条**新增一个 `<slug>.zh.md` 文件**，不改任何代码与目录结构，`npm run build` 后同一条在
   中文界面下显示中文正文，标注消失。

**什么算通过.** 两条都成立。第 2 条是「为未来的翻译做好准备」的可判定形式。

## AC5 — 中英两种界面语言下上述都成立

**怎么查.** AC1 的倒序与条数、AC2 的详情页结构，在中文界面下重跑一遍。
